# SAR-Agent 五分钟演示脚本

> 面向导师/面试官的现场演示流程，串联 prd.md §3 的 S1~S4 四个场景。
> 演示前自查：`python scripts/run_checks.py` 全绿；浏览器打开 <http://127.0.0.1:7860>。

## 0. 开场白（30 秒）

> SAR 图像的舰船判读过去依赖人工，检测模型又只给框、不给解读。SAR-Agent 把
> YOLOv8 的感知能力和 GLM-5.3-Flash 的认知能力接在一起：自然语言指挥、检测、
> 解读、报告全自动，还能记住使用者的偏好。全部跑在 CPU 上，单图 3 秒以内。

## 1. 场景 S1：30 秒看到完整检测能力（Tab1 检测工作台，1 分钟）

1. 选择「内置示例图」下拉框第一张（test 集精选的密集舰船场景）；
2. 点「开始检测」→ 指着屏幕讲三件事：**标注图**（框+置信度）、**明细表**（与图一一对应）、
   **两张统计图**（置信度分布、目标位置分布——位置图能看出空间聚集）；
3. 把置信度阈值从 0.25 拖到 0.5 再检测一次，展示**低分虚警框消失**。

**一句话点评**：界面按钮直调检测器，不经过大模型——所以检测功能永远稳定可用。

## 2. 场景 S2：自然语言的检测与解读（Tab2 智能对话，2 分钟）

依次输入（每条等 Agent 回完再发下一条）：

| 输入 | 亮点 |
|---|---|
| `检测第二张示例图，阈值用 0.3` | Agent 自主决定先列图像再调检测器，回答先结论后细节 |
| `这张图置信度低于 0.35 的目标有几个？` | 追问走的是结构化 JSON，数字与明细表完全一致（防幻觉设计） |
| `结合检测数据说说这个场景可能是什么？` | LLM 的知识整合：区分"事实（工具结果）"与"推断（解读）" |

**一句话点评**：大模型不直接看图——所有数字都来自检测器的结构化输出，这是防幻觉的架构选择。

## 3. 场景 S3：一键报告（Tab2 → Tab3，1.5 分钟）

1. 对话输入：`把刚才的结果生成一份 Word 报告`；
2. 切到「历史与报告」Tab，点「刷新历史」→ 选中该记录 → 报告下载格里就有 .docx；
3. 打开报告：统计表、标注图、两张统计图、Agent 文字解读、方法说明一应俱全。

**一句话点评**：报告由 Jinja2/reportlab/python-docx 渲染，数字与检测 JSON 逐项一致。

## 4. 场景 S4：长期记忆（Tab2，1 分钟）

1. 输入：`记住我以后报告都用 docx 格式，置信度阈值习惯 0.35`；
2. **重启一次 app.py**（最有说服力）→ 刷新页面；
3. 输入：`我的偏好是什么？我之前分析过哪些图？`
4. Agent 凭 SQLite 三层记忆回答偏好与历史。

**一句话点评**：会话缓冲、长期事实、检测档案三层记忆，重启不丢。

## 5. 收尾（30 秒）

> 工程上：8 个 Function Calling 工具、自研 ReAct 循环、SQLite 记忆、三种格式报告、
> pytest 单测与 20 条指令回归、验收自检脚本。数据集是 HRSID+SSDD 合并集 6735 图
> 19435 框。下一步接入自训练权重，做 mAP 对比实验。

## 演示避坑

- 提前跑一遍本脚本，确认 API Key 有效、示例图已加载；
- 多图指令耗时长（Agent 会逐图检测），演示用单图指令；
- 若现场断网：Tab1 检测工作台不受影响，这正是双路径架构的价值；
- 备好一份已生成的报告文件，以防报告环节卡顿。
